## 1. Архитектура и сборка

- **Одна HTML-страница**: three.js 0.160 (OrbitControls, EffectComposer + UnrealBloom для свечения), весь код и все данные встроены в файл. Публикуется как артефакт; версии 1–6 — позы и физика, следующая — круг переходов.
- **Слои проекта:** модель тела `anatomy3.js` (один и тот же модуль работает и на странице, и в сборочных скриптах Node) → решатель поз `poses_build.mjs` → `poses.json` → физика `physics_core.mjs` + `physics_params.mjs`, сборка `physics_build.mjs` → `physics.json` → страница (`app3.js` = верхняя часть + `ui3.js`, шаблон `template3.html`) → `build.py` вставляет модель и данные в шаблон.
- **Принцип:** всё тяжёлое считается при сборке (позы, статика, круг), страница только показывает, интерполирует и считает итоги под выбранную задержку. Данные лежат в JSON и встраиваются как литералы (`/*__POSES__*/`, `/*__PHYSICS__*/`, `/*__CYCLE__*/`).
- **Отладка:** `dist/test.html` — та же страница с `window.__dbg` (камера, слои, выбор, переключение поз, `setOverride` для показа произвольной конфигурации). Скриншоты — Playwright + Chromium со swiftshader (`shot8.py`, `phys_shots2.py`, `shot_conf.py`).
- **Типографика:** функция `nb()` ставит неразрывные пробелы после коротких слов и перед тире — правило пользователя: на визуалах не оставлять висячие предлоги, частицы и тире в конце строки. Применяется ко всем текстам интерфейса и к статичной разметке при загрузке.

```javascript
// app3.js — короткие слова и тире не остаются в конце строки; в кавычках стоит неразрывный пробел U+00A0
const SHORT = 'в|во|и|не|ни|до|на|с|со|к|ко|о|об|от|у|по|за|из|а|но|же|для|при|без|над|под|про|или|как|что|это|то|их|его|её|ее|чем|чём|уже';
const RE_SHORT = new RegExp('(^|[\\s(«„"])(' + SHORT + ')\\s', 'giu');
function nb(s) {
  return String(s).replace(RE_SHORT, (m, a, w) => a + w + ' ').replace(RE_SHORT, (m, a, w) => a + w + ' ')
    .replace(/\s—/g, ' —').replace(/\s–/g, ' –').replace(/—\s/g, '— ').replace(/–\s/g, '– ')
    .replace(/ (\S{1,4})$/, ' $1');
}
```

## 2. Модель тела

### Риг и кинематика

- **59 сегментов**: таз (корень), поясница `lumA`, `lumB`, грудной отдел `thA`, `thB`, `thC`, шея `neckA`, `neckB`, голова; на каждую сторону — ключица `clav`, лопатка `scap`, плечо `hum`, предплечье (лучевая кость `fore`, локтевая `ulna`), кисть `hand`, большой палец `f1m`, `f1a`, `f1b`, пальцы `f2a`…`f5c` (по три фаланги), бедро `thigh`, голень `shank`, стопа `foot`, пальцы стопы `toes`.
- **Локальные кватернионы относительно стойки.** Каждый сегмент знает точку сустава `J` в координатах стойки; прямая кинематика `computeWorld(local, rootQ, rootP)`: мировой поворот = поворот родителя × локальный, позиция = позиция родителя + (J − J родителя), повёрнутое родителем.
- **Зеркалирование:** правая сторона — отражение левой, `mirrorQ(q) = (x, −y, −z, w)`, точки отражаются по x. Позы строятся для левой стороны, правая получается автоматически (`setLR`).
- **Предплечье из двух костей:** кисть висит на лучевой кости. Поворот кисти раскладывается на вращение вокруг оси предплечья (пронация/супинация: `fore = сгибание·twist`, `ulna = twist⁻¹`) и остаток в лучезапястном суставе (`hand = swing`) — так локтевая кость не крутится вместе с лучевой.
- **Размещение на полу** `placeW`: самая низкая метка опоры ставится на y = 0, тело центрируется по длине коврика (z). Для круга добавлено явное место на коврике `rootP`.
- **Массы:** 16 точечных масс по долям тела (голова 6,9 %, грудная клетка 16 %, живот и поясница 16,3 %, таз 11,2 %, плечо 2,7 %, предплечье 1,6 %, кисть 0,6 %, бедро 14,2 %, голень 4,3 %, стопа 1,4 % на сторону); `comOf(W)` — центр масс.
- **Метки опоры** `LANDMARKS`: точки поверхности тела с регионом (ладони, пальцы рук, кулаки, предплечья, локти, пятки, подушечки стоп, пальцы стоп, тыл стоп, колени, бёдра, таз, живот, рёбра, грудь, голова…), тегом (`palm`, `heel`, `toeTip`, `foreElbow`…) и стороной. Контакт с полом — метка ниже 4 мм.

```javascript
// anatomy3.js — прямая кинематика
function computeWorld(local, rootQ, rootP) {
  const W = {};
  for (const s of SEG) {
    const lq = local[s.name] || IDQ;
    if (!s.parent) {
      W[s.name] = { q: rootQ.clone().multiply(lq), p: rootP.clone() };
    } else {
      const P = W[s.parent], par = S[s.parent];
      const off = s.J.clone().sub(par.J).applyQuaternion(P.q);
      W[s.name] = { q: P.q.clone().multiply(lq), p: P.p.clone().add(off) };
    }
  }
  return W;
}
```

### Мышцы, связки, капсулы

- **514 нитей** (обе стороны): **91 мышечный юнит**, **27 связок**, **6 капсул**. Мышца — веер `fan()` из n пучков между полилиниями начала и прикрепления (сырые точки в координатах стойки на сегментах или `auto` — сегмент выбирается по высоте), через промежуточные проводники `via` и с обёртками `wraps` вокруг эллипсоидов (грудная клетка, головка плеча, тазобедренный и голеностопный суставы).
- **Путь нити** `strandPath`: точки переводятся в мир, затем каждый отрезок рекурсивно огибает эллипсоид обёртки (проекция ближайшей точки на поверхность, глубина рекурсии задаётся). Длина пути даёт растяжение относительно стойки `L/L0 − 1` — это режим подсветки «Длина» и основа плеч рычагов в физике.
- **Блоки и проводники**: сухожилия у запястья (удерживатели), проводники трёхглавой мышцы, квадратной мышцы бедра, длинной отводящей большого пальца — чтобы линия действия не перескакивала через ось сустава и плечо рычага не меняло знак.
- **Юниты** (`t3_units.js`): русское название, группа, глубокая или поверхностная (для двух слоёв показа), описание; связки привязаны к суставам (для подсветки при выборе сустава).
- **Анализ суставов**: клинические компоненты (сгибание/разгибание, отведение/приведение, ротации, для лопатки — разворот, наклон, смещение) с нормами подвижности `ROM` и пометками (например, «больше 180° — рука ушла за линию уха»).

```javascript
// anatomy3.js — путь нити с обёртками
function strandPath(W, m) {
  let pts = m.pts.map(q => pt(W, q.seg, q.p));
  for (const w of m.wraps) {
    const out = [pts[0]];
    for (let i = 1; i < pts.length; i++) wrapSeg(W, w, pts[i - 1], pts[i], out, w.depth);
    pts = out;
  }
  return pts;
}
function pathLength(pts) { let L = 0; for (let i = 1; i < pts.length; i++) L += pts[i].distanceTo(pts[i - 1]); return L; }
```

## 3. Позы

### Метод

Каждая поза — функция-построитель в `poses_build.mjs` с таблицей параметров (углы по сегментам позвоночника, положение лопатки, бедро, колено, стопа, кисть). Общие шаги:

1. Позвоночник и шея — повороты сегментов вокруг X (сгибание/разгибание) по таблице.
2. Плечевой пояс — `scapulaPose(up, post, prot, pivot, clavRot, elev)`: разворот лопатки вверх, наклон назад, смещение вперёд/сведение, поворот ключицы, подъём/опускание.
3. Руки — досягание запястья в цель (`aimArm`: треугольник плечо–локоть–запястье, локоть к заданному направлению, несколько итераций для учёта вальгуса предплечья), ориентация кисти (`orientHand`, `bentHand` — ладонь к нормали с разгибанием в запястье, `gripHand` — хват), пальцы (`fingers`: SPREAD — ладонь плоско, FIST — кулак, GRIP — хват, SOFT — мягко).
4. Корпус на полу — наклон корня подбирается бисекцией так, чтобы нужные опоры встали на пол (например, у горки — высота лодыжки 0,115 м при плоских ладонях); `settle` перекатывает тело по нижней выпуклой оболочке меток до положения, где центр масс над опорой.
5. Стопы и пальцы стоп — бисекцией до касания нужных меток (подушечки, пальцы, тыл стопы).

```javascript
// poses_build.mjs — бисекция, на которой держатся подборы углов
function bisect(f, a, b, n = 60) {
  let fa = f(a), fb = f(b);
  if (fa === 0) return a;
  if (fb === 0) return b;
  if ((fa > 0) === (fb > 0)) return Math.abs(fa) < Math.abs(fb) ? a : b;
  for (let i = 0; i < n; i++) { const m = (a + b) / 2, fm = f(m); if ((fm > 0) === (fa > 0)) { a = m; fa = fm; } else { b = m; fb = fm; } }
  return (a + b) / 2;
}
```

## 4. Физика: какие мышцы и насколько включаются

### Постановка

Поза считается **статической**: тело в равновесии, мышцы распределяют нагрузку с наименьшим усилием. Это стандартная в биомеханике статическая оптимизация (одна квадратичная задача на позу), без ЭМГ.

$$
\min_x\ \tfrac12\,x^\top P\,x+q^\top x\quad\text{при}\quad A_{eq}\,x=b,\qquad A_{in}\,x\le 0,\qquad lo\le x\le hi
$$

**Неизвестные x:** активации всех мышечных нитей $a_j\in[\text{тонус};1]$; силы на каждой контактной метке (нормальная N ≥ 0 и две касательные); силы хватов кистью за голень (3 на хват); давление лопатки на грудную клетку (2 точки на сторону, только прижим); резервные моменты по каждой степени свободы суставов (связки, суставные поверхности — дорого, только если мышцам не справиться); масштабы пассивного натяжения групп (опция, выключена).

**Равенства — равновесие по каждой степени свободы k** (6 у корня, 3 × 8 у позвоночника, на сторону: грудино-ключичный 3, плечевой 3, локоть 2 — разгибание и пронация, запястье 2, тазобедренный 3, колено 1, голеностоп 2):

$$
\sum_j R_{jk}F^{E}_j a_j+\sum_{c}\mathbf v_{ck}\!\cdot\!\mathbf F_c+\sum_{g}(\mathbf v^{hand}_{gk}-\mathbf v^{shank}_{gk})\!\cdot\!\mathbf F_g+\sum_{s}(\mathbf v^{A}_{sk}-\mathbf v^{B}_{sk})\!\cdot\!\mathbf n_s F_s+\tau^{res}_k=-\Big(\sum_m \mathbf v_{mk}\!\cdot\!m_m\mathbf g+\sum_j R_{jk}F^{P}_j+\tau^{spine}_k+\tau^{stop}_k\Big)
$$

где $\mathbf v_{\cdot k}$ — виртуальное смещение точки при повороте по оси k (`dpdq`: $\mathbf a_k\times(\mathbf P-\mathbf c_k)$ для вращения, $\mathbf a_k$ для переноса корня).

**Неравенства:** пирамида трения $|t_x|+|t_z|\le\mu N$ (4 строки на контакт, μ по региону); хват только на тягу — сила голени на кисть внутри конуса вокруг линии плечо→кисть: $s_1(\mathbf F\cdot\mathbf e_1)+s_2(\mathbf F\cdot\mathbf e_2)\le c\,(\mathbf F\cdot\mathbf u)$, $s_{1,2}=\pm1$.

**Стоимость (диагональ P):** мышцы $F^{max}_j/1000$ — минимум взвешенной суммы квадратов активаций (большие мышцы берут больше); нормальная сила опоры $0.6/k_c$ — упругая энергия сжатой ткани $N^2/k$; трение 0,3; хваты 0,05; лопатка 0,2; резервы 100; масштабы пассива 0,01.

```javascript
// physics_core.mjs — строка равновесия для степени свободы k
```

### Мышца как двигатель

- **Плечо рычага** — центральная разность длины настоящего пути нити (с обёртками) при повороте сустава:

$$
R_{jk}=-\frac{L_j(q_k+\delta)-L_j(q_k-\delta)}{2\delta},\qquad \delta=0.3^\circ
$$

- **Сила–длина** (гауссиана, ширина как у Thelen 2003), длина волокна относительно стойки с учётом доли волокон φ:

$$
F^{E}_j=F^{max}_j\exp\!\Big(-\frac{(\tilde l-1)^2}{0.45}\Big),\qquad \tilde l=1+\frac{L/L_{stand}-1}{\max(0.3,\varphi)},\ \ \tilde l\in[0.4;1.7]
$$

- **Пассивное натяжение** растянутых длинных мышц (задняя поверхность бедра, икры, передняя голень, сгибатели бедра, пресс, спина, плечо):

$$
F^{P}_j=\min\!\Big(0.8,\ frac\cdot\frac{e^{3u}-1}{e^{3}-1}\Big)F^{max}_j,\qquad u=\frac{e-e_0}{e_{lim}-e_0},\quad e=\frac{L}{L_{stand}}-1
$$

- **Параметры мышц** (`physics_params.mjs`): нижняя конечность — по модели Delp Gait2392, рука и вращательная манжета — Holzbaur 2005, туловище — Christophy 2012, шея — Vasavada 1998, плечевой пояс — van der Helm 1994, мелкие мышцы — по поперечнику ≈ 35 Н/см².
- **Защита знака рычага** (`GUARD_DEF`): при глубоком сгибании (бицепс у 147°, задняя поверхность бедра и икроножная после 90°, большая ягодичная, поясничная и напрягатель широкой фасции при глубоком сгибании бедра) линии модели пересекают ось сустава; там рычаг против анатомического направления обнуляется. Для правой стороны знак сверяется по опорной мышце.

### Пассивные ткани и опора

- **Позвоночник:** диски и связки — пружины по трём осям с жёстким упором в конце диапазона:

$$
M=-k\,\theta-\operatorname{sign}\theta\cdot M_{lim}\,\frac{e^{4u}-1}{e^{4}-1},\qquad u=\frac{|\theta|-0.6\,lim}{0.4\,lim}
$$

- **Упоры суставов конечностей** — потенциальная энергия, обобщённая сила — минус производная по каждой оси (конечными разностями, поэтому не нужны соглашения о знаках): голеностоп (подошвенное сгибание 40–65°), колено (переразгибание 2–10°), локоть (сгибание 135–155°, переразгибание 2–10°), запястье (±50–85°):

$$
U(\theta)=M\,(b-a)\,\frac{\frac{e^{ku}-1}{k}-u}{e^{k}-1},\qquad u=\frac{\theta-a}{b-a},\ k=4,\qquad Q_k=-\frac{\partial U}{\partial q_k}
$$

- **Пол:** контакт — метка ниже 4 мм; жёсткость ткани по региону (`CONTACT_K`: ладони 3, пальцы 1,5, живот 0,7…), трение по региону (`FRICTION`). Начальное распределение вертикальных сил — «упругое основание»: жёсткое тело слегка погружается в мягкий пол, $N_c=k_c(d_0+a x_c+b z_c-h_c)$ с балансом веса и моментов, отрицательные контакты отбрасываются.

### Решатель

ADMM в стиле OSQP (`qpSolve`): разложение Холецкого матрицы $P+\sigma I+A^\top\rho A$, σ = 10⁻⁶, релаксация α = 1,6, для равенств ρ × 1000, адаптация ρ каждые 400 итераций по отношению невязок, остановка при невязках \< 10⁻⁶, до 16–20 тыс. итераций. Для круга агент phys добавил тёплый старт (переменные и двойственные по ключам из соседнего кадра — 50 итераций вместо 550–750) и необязательное сглаживание $w\,F^{max}/1000\,(a-a_{prev})^2/2$ (меняет только раздел нагрузки между взаимозаменяемыми мышцами, равновесие остаётся точным).

### Что выдаётся

- Активация каждого юнита (сила / максимальная сила нитей), пассив, растяжение; моменты по суставам: нужный мышцам, внешний, пассивный, резерв, запас мышц в обе стороны (эффективность = нужный / запас).
- **Реакции в суставах:** сила, с которой проксимальная кость давит на поддерево (массы, опоры, хваты, лопатка, тяги мышц, пересекающих границу). Для L5–S1 и T12–L1 — сжатие вдоль оси позвонка и сдвиг; доля сжатия L5–S1 от мышц и две главные мышцы. Бедренно-надколенниковая сила — сумма направлений тяги четырёхглавой у надколенника и связки надколенника.
- **Тонус по подсказкам** (`CUE_TONE`) — нижняя граница активации: например, в планке четырёхглавые 0,15, прямая мышца живота 0,15, большая ягодичная 0,12.

### Проверка и ограничения

| Поза | Невязка равновесия | Резервы, Н·м | Время |
| --- | --- | --- | --- |
| Стойка | 1,1·10⁻⁴ | 0 | 0,3 с |
| Горка | 0,056 | 1 | 6,7 с — трудный случай: трение ладоней почти равно нагрузке |
| Планка | 1,4·10⁻⁵ | 0,1 | 0,3 с |
| Полупрогиб | 8,6·10⁻⁴ | 0,2 | 0,2 с |
| Корзинка | 4,5·10⁻⁷ | 0,4 | 0,2 с |
| Наклон | 4,5·10⁻⁶ | 0,1 | 0,3 с |

**Известные ограничения:** удлинение трёхглавой при глубоком сгибании локтя завышено (локтевой отросток в модели в 3,7 см от оси); результат горки ограничен трением ладоней; в полупрогибе кисти в 3D не достают до шеи, как на фото (перспектива снимка); модель статическая — инерция не учитывается; раздел нагрузки между мышцами — по критерию наименьшего усилия, не по ЭМГ; индивидуальная гибкость (жёсткость тканей) — общая, масштабы групп выключены.

## 5. Круг переходов

**Задача:** горка → (опустил локти и таз) планка → (лёг на живот, вытянул рёбра, свёл лопатки) полупрогиб → (перехватился) корзинка → (опустил руки и ноги, через планку подшагнул) наклон, и подсчёт, насколько за один круг включились мышцы и связки. Работа разбита на агентов со строгим владением файлами; общий контракт — `CYCLE_SPEC.md`.

### Места поз на коврике (якоря)

Чтобы пять параллельно построенных переходов точно стыковались, места поз зафиксированы до начала работы (`cycle_anchors_build.mjs` → `cycle_keys/anchors.json`). Оси: y вверх, тело смотрит в +z, левая сторона +x.

| Планка на предплечьях | (0; 0,297; 0,011) | Запястья на 5 см впереди запястий горки (0,747); предплечья 0,515 (x ±0,21); пальцы стоп −0,80, большие пальцы вместе |

| Сегмент | Переход и фазы | Длительность |
| --- | --- | --- |
| seg1 | Горка → планка: «Сгибаю локти и опускаю предплечья», «Опускаю таз в планку» (стопы отшагивают ≈ 14 см назад и 6 см внутрь) | ≈ 4 с |

**Формат сегмента** `cycle_keys/segN.json`: `{id, from, to, fps: 10, duration, phases: [{t0, t1, label}], frames: [{t, local {59 сегментов}, root, rootP, grip: [] | ["L","R"], tone?, note?}]}`; первый кадр — якорь начала, последний — якорь конца (точные копии). `cycle_build.mjs` склеивает пять сегментов (общий кадр стыка один), центрирует круг по коврику → `cycle_keys/cycle.json`.

### Инструменты (общие, не меняются агентами)

- `cycle_lib.mjs`: `armIK` (запястье в цель, локоть к полюсу, итерации компенсируют вальгус предплечья), `orientHand` (кисть в мировую ориентацию через поворот предплечья и остаток в запястье), `legIK` (лодыжка в цель, колено к полюсу), `orientFoot`, `fitRoot` (поворот и сдвиг корпуса в сагиттальной плоскости по опорам — решение Прокруста), `asLeft` (правая сторона как отражённая левая — один решатель на обе стороны), `contactsOf`, `effectors`, `summary`. Проверено на пяти позах: кисти и стопы возвращаются с точностью до долей миллиметра; **ограничение** — у почти прямой руки ошибка до 2 см (вальгус), прямые руки строятся от ориентации плечевой кости.
- `cycle_check.mjs` — одни и те же цифры для всех: проникновение в пол (самая низкая метка), «зависания» 4–6 мм (неоднозначный контакт), скольжение опор за кадр и за сегмент, запас ЦМ над многоугольником опоры, наибольший поворот сегмента за кадр, стыки с якорями.
- `shot_conf.py` — рендер любых кадров настоящей страницей (через `__dbg.setOverride`) с неподвижной камеры (вид сбоку, ¾ спереди/сзади, сверху), листы кадров с подписями; браузер запускается по одному (lock), т. к. в среде 2 CPU.
- `cycle_provisional.mjs` — черновой круг простым смешиванием поз (тело проходит сквозь пол) — чтобы физика и интерфейс начали работу до готовых переходов.

### Физика каждого кадра (агент phys)

- Каждый кадр решается как статическая поза на своём месте коврика (`o.rootP`; медленная йога — инерцией пренебрегаем), обе стороны отдельно (переходы несимметричны), тёплый старт от соседнего кадра, сглаживание 0,15.
- **Тонус по подсказкам в переходе:** A — тонус позы, из которой выходим, B — в которую входим, S = min(A, B) по мышце; в первой фазе собственные подсказки A затухают до S, в последней фазе подсказки B нарастают от S:

$$
tone=S+f_A(A-S)+f_B(B-S),\qquad f_A=1-\mathrm{ease}\Big(\frac{t}{t_{1}}\Big),\quad f_B=\mathrm{ease}\Big(\frac{t-t_{last}}{\Delta t_{last}}\Big)
$$

Планка на ладонях (не удерживаемая поза) берёт подсказки прямой линии планки без кулака: четырёхглавые 0,15, прямая мышца живота 0,15, большая ягодичная 0,12. Хваты — по полю `grip` кадра.

- **По кадру сохраняется:** активация и растяжение каждого из 91 юнита слева и справа, натяжение 27 связок и 6 капсул (`L/L0 − 1`, максимум по нитям), силы опоры по регионам, хваты, ЦМ и запас опоры, сжатие и сдвиг L5–S1 и T12–L1, реакции в тазобедренном, коленном, голеностопном, плечевом, локтевом и лучезапястном суставах (в весах тела), невязка, резервы.

### Итоги за круг

`cycle_stats.mjs` интегрирует по кадрам (трапеции по времени) и даёт для каждого юнита: пик и момент пика, интеграл активации (a·с), время с a ≥ 8 %, 20 %, 40 %; значения в пяти удерживаемых позах; растяжение. Для связок — пик натяжения, время с натяжением ≥ 2 % и ≥ 5 % сильнее стойки. Страница пересчитывает итоги под задержку H секунд в каждой позе:

$$
\text{пик}=\max(\text{пик}_{\text{переходов}},\ a_{\text{поз}}),\quad \int a\,dt=\text{int}+H\sum_{\text{поз}}a,\quad t_{\text{работы}}=t_{08}+H\cdot\#\{a\ge0.08\},\quad \bar a=\frac{\int a\,dt}{T+5H}
$$

### Страница: режим «Круг» (агент ui)

- Вкладка «Круг», проигрыватель: пуск/пауза, шкала всего круга с отметками фаз и поз, подпись текущей фазы, скорость 0,5× / 1× / 2×, пауза ≈ 1 с в каждой позе, петля с затуханием; без автозапуска при reduced motion.
- Между сохранёнными кадрами (10 в секунду) — slerp локальных поворотов и корня, линейно место на коврике; камера мягко следует сбоку.
- Подсветка «Усилие» — по активации своей стороны в текущем кадре; «Длина» — по геометрии; силы опоры и хваты по кадрам; карточки мышцы, связки и сустава с графиком по кругу; карточка «За один круг» с выбором задержки 0 / 5 / 15 / 30 / 60 с.
- **Упаковка** (`cycle_pack.mjs` → `cycle_data.json`, вставка `/*__CYCLE__*/`): кватернионы Int16 × 32767, место таза Int16 в 0,1 мм, активации Uint8 × 255 (обе стороны), натяжение связок Int16 × 4000, хваты битами, силы опоры и нагрузки суставов — Int16/Uint8; всё в base64.

**Одна команда для всего круга:** `./cycle_run.sh [--prov] [--every N]` → `cycle_build.mjs` (склейка и центрирование) → `cycle_phys.mjs` под общим замком (статическая оптимизация каждого кадра с тёплым стартом и сглаживанием) → `cycle_stats.mjs` → `cycle_physreport.mjs` (якоря против physics.json, резервы, мерцание, топы). Около 3 мин.

**Определения итогов** (`cycle_stats.json`):

- `peak` — максимум 3-кадровой скользящей медианы: значение, которое держится хотя бы 0,2 с; одиночный кадр-выброс считается сбоем позы этого кадра. `peakRaw` — простой максимум, выбросы перечислены в `spikes`.
- `int` — интеграл активации по времени (a·с), `t08/t20/t40` — время с активацией ≥ 8/20/40 %; для связок `t02/t05` — время с удлинением ≥ 2/5 %.
- «За круг» при задержке H в каждой из 5 поз: пик = max(пик переходов, значения поз); интеграл = int + H·Σ поз; время в работе = t08 + H·(число поз с a ≥ 0,08); среднее = интеграл / (T + 5H).
- Связки и капсулы — изменение длины пути волокна к стойке, не деформация ткани; на странице подписано «удлинение относительно стойки», капсулы — отдельной группой.

**Проверка:** пять кадров-якорей совпадают с physics.json (|Δa| ≤ 0,003); 46 кадров с резервом > 5 Н·м, все объяснены (см. «Анализ модели по пяти книгам», раздел ограничений).

## 11. Детальный череп (версия 8)

**Решение:** череп строится не из примитивов-эллипсоидов, а как поле расстояний (SDF) из ~35 простых форм с плавным объединением и вычитанием, которое при загрузке страницы превращается в сетку методом surface nets. **Почему:** так получаются настоящие впадины (глазницы, грушевидное отверстие, височные ямки, нижнечелюстная ямка, большое затылочное отверстие) и плавные переходы между костями, а данные не раздувают страницу — в неё попадает только ~12 КБ кода. **Что отвергли:** заранее посчитанную сетку в файле (~0,5 МБ base64) и сторонние модели черепа (лицензии, вес).

- Состав: свод (лобная выпуклость, теменные бугры), основание, надбровные дуги и глабелла, глазницы с подглазничными отверстиями, носовые кости и грушевидное отверстие, верхняя челюсть с альвеолярной дугой, скуловые кости и дуги, височные ямки и линии, сосцевидные и шиловидные отростки, наружный слуховой проход, нижнечелюстная ямка, наружный затылочный выступ, большое затылочное отверстие; швы — венечный, сагиттальный, ламбдовидный, чешуйчатые — неглубокими бороздами по своду.
- Нижняя челюсть отдельной сеткой: тело с альвеолярной частью, подбородочный выступ, подбородочные отверстия, ветвь, венечный и мыщелковый отростки, вырезка. Зубы — 32, по 8 в каждом квадранте, своим материалом.
- Сетка: шаг 2,3 мм (череп), 1,7 мм (челюсть), 1,1 мм (зубы); грубый проход через 4 ячейки отсекает точки далеко от поверхности, вершины один раз подтягиваются на поверхность по градиенту. Построение ≈1,4 с, ~51 тыс. вершин.
- Совместимость: точки крепления мышц, метки опоры и массы головы не менялись — физика и позы прежние.

```javascript
// плавное объединение: так кости переходят друг в друга без шва
const smin = (a, b, k) => { const h = max(k - abs(a - b), 0) / k; return min(a, b) - h * h * k * 0.25; };
const smax = (a, b, k) => -smin(-a, -b, k);   // плавное вычитание: глазницы, ямки, отверстия
```

## 12. Череп ещё детальнее (версия 9)

**Решение:** построение черепа вынесено в фоновый поток (Web Worker из Blob с исходником `skullData`), пока он строится, виден простой череп; если поток недоступен, череп строится в основном потоке. **Почему:** детальная сетка (~85 тыс. вершин) строится ~3 с — страница не должна замирать. **Нормали** берутся из градиента поля расстояний, а не из треугольников — поверхность гладкая без ступенек сетки. **Затенение впадин** — цвет вершины по значению поля на небольшом отступе по нормали (глазницы, носовая полость, швы темнее).

- Добавлено: конусы глазниц до зрительного канала, верхняя и нижняя глазничные щели, надглазничная вырезка; носовая полость с перегородкой, средней и нижней раковинами, передняя носовая ость; клыковые ямки и возвышения, альвеолярные возвышения над корнями; лобные бугры, лобный отросток скуловой кости и скуловой отросток лобной; конический сосцевидный отросток, слуховой проход каналом; височные и верхняя выйная линии валиками по своду; швы зубчатые (зигзаг вдоль кривой на своде).

- Зубы по форме: резцы — долотообразные, клыки — конусом, премоляры — с двумя буграми, моляры — с четырьмя буграми и бороздой.

## 15. Стойка на руках (версия 12, 21 октября)

**Решение:** шестая поза «Стойка на руках» (Адхо мукха врикшасана) — отдельная вкладка со своей физикой, мышцами, связками, подсказками и примечаниями. В круг она **не** включена: нужен новый переход из наклона. **Почему так:** запрос «добавь стойку на руках» без уточнений, пользователь не на связи; самый простой смысл — добавить позу, как предыдущие пять. **Что отвергли:** продлить круг стойкой (требует нового сегмента seg6, хват и равновесие на руках — отдельная работа).

### Как построена поза

- `buildHandstand` в `poses_build.mjs` (экспортируется; запуск самого файла защищён проверкой, чтобы его можно было импортировать скриптами подбора). Тело строится лицом в +z вверх ногами: корень `Z(180°)·X(наклон)`, итоговый корень `Y(180°)·…` — тогда бегунок «из стойки в позу» переворачивает тело вперёд, как в остальных позах, а левая сторона остаётся на +x.
- Руки вертикальны в мире: плечо поворачивается на `180° + наклон + сумма углов позвоночника − наклон рук` относительно грудной клетки (сумма углов — потому что грудная клетка наклоняется вместе со спиной), затем отведение и наружная ротация плеча 45°. Ключицы и лопатки — по `scapulaPose` (разворот вверх 46,5°, ключица поднята на 20,6°).
- Кисть: ладонь плоско на полу, пальцы вперёд (`orientHandTw`: пронация предплечья подбирается бисекцией так, чтобы лучевое отведение запястья было 0). Это даёт разгибание запястья ≈ 97°, у модели норма 70°: иначе ладонь под вертикальным предплечьем плоско не лежит.
- Ноги вместе: приведение бедра подбирается бисекцией до касания больших пальцев (зазор 3 мм), носки вытянуты (подошвенное сгибание 48°, пальцы стоп 12°). Наклон всего тела подбирается бисекцией так, чтобы центр масс был на заданном расстоянии впереди запястья (`comAhead`).

```javascript
// poses_build.mjs — руки вертикально в мире, ладони плоско
const RTH = qAx(X, -(180 + st.tilt + spineSum - p.armTilt)).multiply(qAx(Z, p.thAbd)).multiply(qAx(Y, p.thER));
left.hum = left.clav.clone().multiply(left.scap).invert().multiply(RTH);
// пронация: бисекция до нулевого лучевого отведения запястья
st.pron = bisect(devAt, -110, 110);
orientHandTw(L, left, rq, V(0, 0, 0), handBasis(V(0, 0, 1), V(0, -1, 0)), IDQ, st.pron);
```

### Запястье за 90° и упоры суставов для одной позы

- **Ошибка отображения:** в `analyzeJoint` угол разгибания запястья за 90° считался через арксинус и «складывался»: 97° показывалось как 83° и «−180° отведения». Исправлено: ветка запястья считает полный диапазон до 180°. Остальные пять поз пересчитаны — совпадают с `poses.json`.
- **Упоры суставов на позу:** в `physics_core.mjs` параметр `o.stops` заменяет упоры названных суставов только для этого решения. Для стойки запястье: разгибание упирается с 70° до 100° с моментом 20 Н·м (растянутые сухожилия сгибателей и капсула ладони берут часть нагрузки), сгибание — как раньше. Остальные позы и круг не затронуты (`POSE_STOPS` в `physics_params.mjs`).

```javascript
// physics_params.mjs
export const POSE_STOPS = {
```

### Подбор положения тела (hs_opt.mjs)

- Параметры поиска: углы позвоночника (`thA`, `thB`, `thC`, `lumA`, `lumB`), разгибание бедра, наклон рук, положение центра масс над ладонью, лопатка (назад, вперёд, вверх, подъём ключицы). Поиск координатный: для каждого параметра пробуются шаги вверх и вниз, пока цель улучшается; два круга, ≈ 3 мин.
- **Цель:** сумма усилия мышц, резервов суставов и нагрузки на L5–S1 с жёсткими условиями: запас опоры ≥ 3 см, отклонение линии запястья–лодыжки ≤ 9 см, разгибание запястья ≤ 97°. Первый запуск без этих условий уезжал в позы с запасом опоры 1 см и сильным наклоном.
- **Итог:** `thA −10, thB 8, thC 6, lumA 5, lumB −5, бедро 7°, наклон рук −5,5°, центр масс на 5 см впереди запястья, лопатка назад 20° вперёд 4° вверх 46,5°`; руки поставлены на ширину плеч подбором `thAbd = −2` (при +2 кисти были на 39 см при плечах 30 см). Значения записаны по умолчанию в `HSTAND`, `node poses_build.mjs handstand` воспроизводит позу без переменных.

### Ограничения этой позы

- **Запястье** разогнуто на 97° при норме модели 70°: в подписях сказано, что угол глубже нормы и его нужно готовить.
- **Нагрузка на позвоночник завышена или нет — модель не знает.** Поднятые руки сильно растягивают широчайшую и большую грудную (пассивно ≈ 14 и 9 кг), это даёт большой момент на грудной отдел и сжатие L5–S1 2,5 веса тела. Те же натяжения есть в горке, но там они не складываются с весом всего тела на руках. В подписях это названо оценкой модели; у гибкого плечевого пояса натяжение меньше.
- **Двуглавая держит прямой локоть** (47 %): упор локтя в модели включается только при переразгибании больше 2°, а в стойке локоть выпрямлен точно. В жизни локоть упирается в кость, поэтому работа двуглавой, вероятно, меньше расчётной.
- **Мелкие мышцы предплечья** работают на 70–90 % при малой силе (ладонная мышца 92 %, сила 2,5 кг): в списке «Работают сильнее всего» мышцы слабее 150 Н не показываются.
- **Колени** прямые, но расходятся на ширину таза при сведённых стопах (бедро приведено на 3,4°).
- **Подпись бегунка** справа — «На руках» (поле `short` в записи позы), чтобы не повторять «Стойка» слева.

## 16. Работающие мышцы — зелёным (версия 13, 21 октября)

**Решение:** мышца, которая работает (усилие ≥ 8 % максимальной силы, порог `ACTIVE_MIN`), окрашивается в зелёный в любой позе и в круге. **Почему:** запрос «отметь зелёным цветом мышцы, которые работают». Раньше работу показывала только пульсация, а оранжевый и голубой свет — длину мышцы.

- **Как сделано:** у каждой мышечной нити хранятся два набора цветов вершин (обычный красный и зелёный, сухожилия остаются светлыми); `Strand.setOn(on)` переключает массив цветов только при смене состояния, поэтому в круге покадровая смена не дорога. Работа считается по усилию при текущем положении бегунка (ближе к позе — больше зелёных), в круге — по кадру и по стороне.
- Режим «Длина» (открывается по умолчанию): у неработающих мышц свет по-прежнему оранжевый или голубой, у работающих — почти полностью зелёный (примесь цвета длины 10 %) и не слабее заданного свечения. Первый вариант с примесью 60 % зелёного терялся среди оранжевого и голубого, на модели читалось как грязно-оливковый, поэтому примесь уменьшена до 10 %. Цена: у работающей мышцы цвет больше не показывает длину, она видна только по яркости. Режим «Усилие»: свет зелёный, яркость зависит от доли максимальной силы.
- Интерфейс: цвет `--work` (#3fdc86); метка «работает» в карточке мышцы, точка в легенде, проценты и полоски «Усилие мышцы» и «Работают сильнее всего» тоже зелёные; для суставов (золото) и связок (тёплый) цвета прежние. Зелёный не единственный признак — мышца ещё пульсирует и отмечена текстом, потому что зелёный и оранжевый трудно отличить при дальтонизме.

## 17. Объёмные мышцы и поверхности мягких тканей

**Решение:** форму мышц показывают отдельные объёмные поверхности: 85 расчётных юнитов по BodyParts3D 4.0 и 6 явно обозначенных геометрических реконструкций (`lat`, `multifidus`, `ql`, `rectAbd`, `intObl`, `transAbd`). Покрыты обе стороны всех 91 юнитов. Связки показаны лентами, капсулы — цельными оболочками. Готовый скелет сохранён.

**Почему:** отдельная трубка на каждую расчётную нить не воспроизводила внешнюю форму широких мышц, головок и сухожильных переходов. Внешняя сетка и физиологический поперечник — разные данные: замена формы не должна незаметно менять максимальную силу мышцы или распределение силы между её нитями.

- `muscles/build.py` получает те же преобразования костей, что существующие костные сборщики, с загрузкой и сохранением, заменёнными только в памяти. Готовые кости, позы и физика не переписываются. Мышечная сетка переносится непрерывной смесью восьми ближайших костных преобразований; крайний вес равен нулю. Таблица источников, отчёт о покрытии и ограничения — в `muscles/`.
- Пакет содержит 246 частей, 213 994 треугольника. В браузере они объединяются в 182 выбираемые поверхности по юниту и стороне. Сетки встроены в HTML; исходные OBJ для просмотра не нужны.
- `muscle_surface_render.js` привязывает каждую связную часть к постоянному набору не более четырёх анатомических сегментов. В набор обязательно входят опоры проксимального и дистального краёв; крайние участки плавно закреплены за ними, чтобы длинное сухожилие не утягивало брюшко от предплечья к пальцам. Веса плавные; ориентация следует костям. Расчётные прикрепления и проводники определяют опоры, длина пути — небольшую ограниченную поправку толщины. Линейная деформация остаётся приближением: не гарантирует сохранение объёма и контакт тканей при глубоком сгибании.
- `connective_surface_render.js` строит 51 поверхность связок и 12 оболочек капсул из прежних путей и креплений; передний сектор коленной капсулы не замыкается. Фасции и линии Майерса сохраняют отдельный существующий слой. Ленты, складки и удлинения — геометрические оценки, силы фасций в оптимизацию не добавлены.
- `strandPath()` и `ownedStrandPath()` теперь используют один алгоритм в `anatomy3.js`. Длина и плечо рычага вычисляются по тем же точкам, по которым реакции учитывают принадлежность силы сегментам; дублирующий алгоритм в физике удалён. Все 514 прежних нитей и их геометрия сохранены.
- Слои, выбор мышц нажатием, карточки, зелёная активность и круг работают с новыми поверхностями. До загрузки либо при отсутствии декомпрессора остаётся схема пучков с явной подписью. Происхождение формы показывается в карточке и общей подписи.
- `template3.html` стал полным HTML-документом с UTF-8, viewport и сбросом внешнего отступа. `index.html` и `test.html` имеют одинаковую обёртку; отладочный API добавляется только во второй.

**Что отвергли:** подгонку максимальных сил, упоров и крепления трицепса ради ожидаемых процентов; представление реконструкций как исходных анатомических сеток; отдельные вращающиеся каркасы вдоль силовых путей и выбор ближайших узлов на каждой вершине — на коротких путях большого пальца они давали перевороты, на широких мышцах изломы. Также отвергнуто изменение скелета ради устранения остаточной несовместимости подгонки шеи и ключицы. Подробный разбор — `docs/soft-tissues-accuracy.md` и `muscles/README.md`.

**Проверки:** `muscles/check.py` проверяет источник, распаковку и покрытие; `muscle_paths_test.mjs` — единый маршрут длины и силы; `connective_surface_check.mjs` — крепления, ориентацию и швы оболочек; `muscle_surfaces_test.mjs --actual --all-vertices` — всю деформированную геометрию в позах и выборке круга. `ui_soft_tissues_test.py` открывает настоящую страницу в Chromium на размерах компьютера и телефона, проверяет слои, выбор нажатием, карточки, промежуточные состояния, кадры круга и публичный HTML. Эти проверки подтверждают согласованность реализации, а не клиническую точность модели.

**Ограничения:** групповые юниты сохраняют одну оценку усилия для нескольких анатомических частей; правая длинная мышца шеи отражена из левой. Остаточные особенности подгонки SCM и микроскопические рёбра после квантования перечислены в отчёте. Усилия остаются оценками прежней статической модели; ЭМГ, инерция, индивидуальная гибкость и передача фасциальной силы не добавлены.

## 18. Крупный план мышц: швы, форма и материал

**Проблема:** на крупном плане стойки на руках мышцы выглядели как ребристые плоские ленты с белыми угловатыми полями. Это были несколько разных ошибок: поперечный рисунок текстуры, окраска широкого веера по одной расчётной нити, раздельные вершины на швах исходного OBJ и привязка всей связной части только к четырём сегментам.

**Решение:** исправлять источник, привязку и материал отдельно, сохраняя готовый скелет, физические пути, параметры и оценки нагрузки.

- Перед упрощением исходных мышечных OBJ объединяются только вершины с точно совпадающими координатами внутри одной части. Различные UV и нормали больше не разрывают геометрическую топологию. Координаты исходной поверхности не сглаживаются. Широким и длинным мышцам туловища выделяется больше треугольников; согласованное деление длинных рёбер позволяет поверхности изгибаться между анатомическими опорами.
- Грудино-ключично-сосцевидная поверхность переносится по своим анатомическим опорам — черепу, ключице своей стороны и рукоятке грудины. Прежнее общее поле ближайших костей ошибочно включало задние шейные позвонки и растягивало переднюю мышцу шеи. Это правка регистрации поверхности; готовые кости и расчётные прикрепления не перемещаются.
- В браузере совпадающие вершины одной исходной части получают одинаковую привязку. Нормали сглаживаются на таких швах с сохранением противоположных сторон тонкой оболочки. Четыре влияния выбираются для каждой вершины из всех анатомических сегментов мышцы; компактное поле весов плавно обращается в ноль при смене четвёртой и пятой опоры. Ограничение четырьмя сегментами для всей мышцы удалено: оно теряло часть прикреплений широких вееров и длинных мышц спины.
- Реконструкции получили округлые края и плавные переходы толщины. Пять путей широчайшей согласуются по общим направляющим, поэтому промежуточное сечение не соединяет разные участки соседних путей. Торцы следуют изогнутому сечению, а не вееру через произвольную среднюю точку. Перетяжки прямой мышцы живота стали неглубокими.
- Низкоконтрастные продольные волокна заменили поперечные полосы; используются mipmap-фильтрация и анизотропия. Размер рисунка задан в координатах поверхности. Светлая окраска ограничена окрестностью прикреплений вместо проекции всего веера на одну нить; условность этой окраски указана на странице. Три сухожильные перемычки прямой мышцы живота отмечены локально по прежним `dips`; узкая фрагментная маска не зависит от шага сетки. Зелёная активность и режимы подсветки сохранены.

**Что отвергли:** скрытие проблемных мышц, обрезание атласных частей, изменение готовых костей и подгонку силовых параметров ради внешнего вида; сварку близких, но различных координат, которая могла бы склеить тонкие слои; сглаживание всей исходной формы и глобальное увеличение плотности всех мышц. Деформация остаётся геометрическим приближением, реконструкции не становятся данными атласа, направление текстуры одного юнита не является измеренным полем мышечных волокон.

**Проверка:** сравнение одинаковых крупных планов до и после; отсутствие раскрытия совпадающих швов в позах и кадрах круга; регрессии широкого веера с более чем четырьмя опорами, тонких противоположных поверхностей и прикреплений сгибателей пальцев; целостность упакованных данных, формы относительно исходного атласа и обычные браузерные проверки поз, слоёв и выбора нажатием. Эти проверки подтверждают устранение ошибок реализации, а не независимую анатомическую точность.

## 19. Суставные поверхности и оболочки связок

**Проблема:** после подключения настоящих костей сохранились независимые эллипсоиды хрящей, круглые торы менисков и трубчатые капсулы. Они не совпадали с готовым скелетом даже в стойке. Обычная интерполяция между путями капсулы дополнительно срезала эллипсоид огибания в согнутых позах.

**Решение:** сохранять готовые кости, оси и силовые пути, а суставные поверхности строить отдельным геометрическим слоем.

- `joints/build.py` выделяет региональные участки из неизменённого `skull/bones_bp3d.json` и формирует тонкие покрытия для плеча, локтя, запястья, бедра, колена и голеностопа. Губы реконструируются по краю впадин, мениски — открытыми клиновидными полумесяцами около плато большеберцовой кости. Все части отмечены `source: reconstructed`; происхождение и параметры находятся в `joints/`.
- В проверенных таблицах и OBJ BodyParts3D нет требуемых хрящей конечностей, менисков, губ и капсул. В источнике найдены межпозвонковые диски, длинная подошвенная связка и удерживатель сгибателей, но их наличие не даёт исходных сеток остальных тканей. Позвоночник и мелкие суставы в этой доработке сохраняют прежнюю схему.
- `joint_surface_render.js` распаковывает статические сетки и перемещает каждую вместе с назначенной костью. Форма поверхности не участвует в решателе, не меняет суставной зазор и не уточняет оценки нагрузки. Сжатие хряща, контакт, скольжение менисков и деформация губ не моделируются.
- Замена прежних покрытий происходит после успешной загрузки, по точной паре `сегмент|название`. Удалённая геометрия исключается из сцены, массивов выбора и подсветки; при ошибке загрузки остаётся схема с явной подписью. Слой суставов, карточки, выбор нажатием и подсветка используют новые поверхности.
- Поверхности связок сохраняют исходные пути, но получают замкнутые торцы, округлые сечения и общие веера широких пучков. Между путями капсулы интерполируется направление в системе эллипсоида огибания: это уменьшает дополнительное проникновение оболочки, не изменяя сами расчётные пути. Складки и подмышечный запас оболочки — приближения отображения.
- Для 12 оболочек капсул отдельно подготовлены края по ограниченным суставным участкам готовых костей (`joints/capsule-rims.json`). Они заменяют прямые свободные края прежних цилиндрических оболочек. Геометрические опоры и огибание отделены от механических: `part.displayPaths` описывает геометрические пучки, `part.displayColumnPaths` — все отображаемые колонки оболочки; `part.paths`, длина, натяжение и силы сохраняют исходные пути. Эти две длины не выдаются за одну измеренную деформацию. Невалидная подгонка возвращает прежнюю схему с явным статусом.
- На кость проецируются все отсчёты отображаемого края, включая промежуточные между исходными пучками. Для каждой колонки оболочки строится отдельный геометрический путь: угловая интерполяция только редких опор отрывала промежуточный край от кости на 9–14 мм. Резкая поправка первых двух рядов отвергнута, поскольку создавала короткие отвороты. Отдельная обратная матрица для координат эллипсоида учитывает слегка ненормированные кватернионы упакованного круга; сами кватернионы и физика не меняются.

**Уточнение раздела 17:** незамкнутый сектор исходной коленной капсулы находится медиально, а не спереди. Подгонка отображаемого края к кости сохраняет порядок исходных пучков и не реконструирует передний аппарат надколенника. Нельзя называть эту поверхность полной анатомической капсулой с правильным передним отверстием.

**Что отвергли:** выдачу восстановленных покрытий за исходные ткани BodyParts3D; перемещение готовых костей ради искусственного суставного зазора; изменение креплений, жёсткости и численных сил ради картинки; закрытие отверстий менисков и неизбирательное скрытие старых поверхностей всех суставов. Локальные пересечения из-за готового рига и условных путей остаются ограничениями.

**Проверка:** целостность пакета и его привязка к исходным костям; жёсткая привязка всех вершин во всех позах и выборке круга; сохранение отверстий и статических буферов; исходные точки пучков, замкнутые торцы, огибание и независимость от положения тела; браузерные слои, выбор, подсветка, резервный вид и одинаковые крупные планы до/после. Это проверка реализации, не независимая анатомическая или биомеханическая валидация.

## 20. Проверяемый расчёт и первичные исследования 2025–2026

**Задача:** улучшить модель на основании современных работ, сохранив готовый скелет. Реестр девяти первичных источников с датами, университетами, лицензиями и пределами применимости — `research/2025-2026/sources.json`, разбор — `docs/research-2025-2026.md`. В частности, NMSM Pipeline (Rice, Stanford, UC Davis, 2025) различает персонализацию по данным и неоднозначность силы/возбуждения; исследования чувствительности и мягких тканей показывают зависимость выходов от допущений. Они не дают универсального процента точности для йоги.

**Исправления реализации:**

- Старый QP мог закончить итерации с малым остатком равенств и нарушенным неравенством. Теперь отдельно проверяются равенства, неравенства, границы переменных и прямой/двойственный остатки после окончательного ограничения переменных. `qpSolveVerified` делает один детерминированный повтор с продолжением; неуспех прерывает генерацию. Статус, допуски и история попыток сохраняются. Остатки сил и моментов выводятся раздельно в Н и Н·м, резервные моменты — отдельно от них.
- Контакты стоп/ладоней вместо четырёх граней `|Fx|+|Fz|≤μN` используют вписанный в кулоновский круг 16-угольник. Прежнее приближение урезало диагональную силу до `μN/√2`; новое остаётся консервативным с максимальным радиальным недобором `1−cos(π/16)≈1,92%`. Коэффициенты трения сохранены. Выбор 16 граней — наше геометрическое решение, не параметр из статьи.
- Пассивные моменты позвоночника получаются как `−∂U/∂q` для фактических родительских осей. Прежние покомпонентные моменты Эйлера не были согласованы при смешанных вращениях. Жёсткости и пределы прежние; проверены производная энергии и работа по замкнутому пути.

**Опубликованные входы и независимые эталоны:** геометрия Cases 1/2 Gonçalves et al. (онлайн август 2025, выпуск апрель 2026, CC BY 4.0) перенесена из Tables 1/2/3/5 в `benchmark-geometry.json`. `physics_reference_geometry_test.mjs` вызывает настоящие функции пути, принадлежности точек, вращения и передачи силы: 968 конфигураций, 20 отдельно выведенных аналитических эталонов. Прикладной шаг 0,3° даёт ошибку плеча до 5,19·10⁻⁷ м в этих задачах. Это проверка компонента. Авторские силы/активации, Hill-модель и кубический критерий напряжений не воспроизводились; отдельные TSV IFToMM с ограниченными условиями использования не импортировались.

**Сценарии и интерфейс:** `physics_build.mjs` экспортирует `buildPose`, без записи данных при импорте. `physics_sensitivity_build.mjs` рассчитывает стойку и шесть поз с `CUE_TONE` и без этих минимумов: 14 решений, 91 мышца, 8 реакций суставов, 2688 диапазонов метрик. Пакет содержит хеши входов; `physics_sensitivity_test.mjs` сверяет базовый сценарий с `physics.json`, полноту, конечность чисел и полный баланс опоры до округления/фильтрации контактов. Диапазон — минимум и максимум двух сценариев, не доверительный интервал и не граница всех ошибок. На странице пары доступны только при `t=0` (стойка) и `t=1` (полная поза); при движении ползунка, подмене конфигурации и в круге они скрываются. Существующее `a` обозначает активную силу/`Fmax`; отдельное `activation` — усреднённую внутреннюю переменную решателя. Цвет активности продолжает использовать `a`.

**Пересчёт:** заново получены `physics.json`, все 262 кадра и пять удержаний `cycle_phys.json`, статистика, фасциальные показатели и `cycle_data.json`. Все решения имеют статус `solved`; максимальные остатки круга 8,85·10⁻⁴ Н и 5,44·10⁻⁴ Н·м. В 44 кадрах сумма резервов превышает 5 Н·м, максимум 123,8 Н·м — это сохраняющееся ограничение, не погрешность решения. В 226 кадрах есть выход длины мышц за диапазон упрощённой кривой. `cycle_run.sh` теперь завершает расчёт обновлением фасциальных показателей и упаковкой, чтобы страница не получила прежний пакет. Упаковка проверяет диагностику перед встраиванием.

`cycle_quality.mjs` отклоняет неполный выпуск, невалидные числа, противоречие статусу/допускам, неверные индексы и времена и отсутствие пяти удержаний. Явно прореженный `--every N` остаётся предварительным просмотром с `verified: false`, без утверждения о проверке всех кадров. У реакций суставов устранено прежнее молчаливое обрезание выше 5,1 веса тела: масштаб байтов выбирается по фактическому максимуму и передаётся уже поддерживаемому декодеру. Для текущего круга масштаб равен 49, максимальная ошибка квантования ≤0,01021 веса тела. `node cycle_quality_test.mjs --packed` сверяет каждый упакованный канал с исходным расчётом и содержит негативные примеры неполных/невалидных данных. Численные снимки и отчёты `books/yoga_*` обновлены; ручные таблицы удержаний обозначены историческим разбором, который заново не валидировался.

**Что отвергли:** перенос процентов ошибки из ходьбы/подъёма руки на йогу; подбор `Fmax`, жёсткостей, длины сухожилия или прикреплений до ожидаемых процентов; представление двух сценариев как статистического интервала; объявление малой невязки физиологической валидацией; импорт сеток и кода без проверенной лицензии. Новые материалы исследований не подменяют анатомию готового скелета.

**Ограничения:** модель остаётся общей и квазистатической, без ЭМГ, инерции и индивидуальной калибровки. В промежуточных состояниях поз усилия интерполируются. Сохранены ограничения кривой силы–длины, нижняя граница доли волокон, защиты знака некоторых рычагов и прежняя механика суставных упоров. Геометрическое удлинение связки/капсулы относительно стойки не равно растяжению ткани; контакт, давление и сжатие тканей не добавлены. Исследования и тесты не делают модель клинически или персонально подтверждённой.
